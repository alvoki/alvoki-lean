Native disk snapshot session check experiment
Baseline commit: 7d078a0 (Audit abstract WAL replay refinement)
Checked commit: 6c4ca0e (Bind disk snapshot handles to their open session)
Integrated runtime commit: 1095c3b7ace79701e3aa6b565cc060d4344fb113 (same measured runtime patch).
Linux 6.18.57 x86_64, AMD EPYC 9V74, five visible CPUs, 4 CPU cgroup quota, Lean 4.36.0.
CSV columns: pair index, position within pair, variant, total point-loop ns, total range-loop ns.
One directory seeded through the old DiskTable API with a 256-row single-run checkpoint.
Each process opens that directory, acquires one pin, then independently warms both workloads.
The point loop executes 1,048,576 valid evenly permuted point reads.
The range loop executes 131,072 valid eight-row windows, evenly cycling through the run.
The loops sum returned payloads. Acquisition, warming, and checksum assertions occur outside the timed intervals.
Each CPU has 14 pairs. Pair order alternates between baseline first and checked first.
The measurements are elapsed wall time, including any scheduling delays.

Copy this directory into a temporary directory before reproducing, so the
binaries and trial CSVs are written there. Use checkouts of the baseline and
integrated runtime commits. Set ALVOKI_TOOLCHAINS to the pinned toolchain
directory if it is not adjacent to the checkouts at ../work/toolchains.
Run bash build.sh PATH_TO_BASE_WORKTREE base and
bash build.sh PATH_TO_CHECKED_WORKTREE checked from that directory.
Run ./base setup database once with no database directory present.
Run python3 run.py 4 cpu4 and python3 run.py 1 cpu1 on idle, available cores.
