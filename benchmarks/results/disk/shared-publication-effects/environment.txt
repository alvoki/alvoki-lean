Native publication dispatcher comparison
Platform Linux-6.18.57-x86_64-with-glibc2.41, AMD EPYC 9V74, CPU 1, pinned Lean 4.36.0.
Baseline runtime 488d2a6898dedefa8488cb1c1e000b4b021d79a7.
Measured candidate 74b5fc5c9b001356e6389f0ddb265d61a30e5dc0.
Integrated runtime commit 6ae0c1a3a14290fea87dc9cf0eb49d2d8433f46f with the same measured change.

Write and checkpoint use 12 alternating pairs of processes with three native
trials each. The write process measures 32 acknowledged writes per trial. The
checkpoint process publishes four runs of 32 rows. Reported relative times are
the medians of the candidate-to-baseline ratios for paired process medians.
Reopen uses 14 alternating pairs per workload. Each marked WAL has 32 or
2048 records and is either aligned or includes a torn tail.

Build alvoki-disk-write, alvoki-disk-checkpoint and alvoki-disk-replay at both
commits with the repository's pinned Lake. Copy the experiment into a temporary
directory before rerunning. Run python3 compare_write_checkpoint.py with the
absolute baseline and candidate lean/.lake/build/bin paths. For reopen, use
the adjacent shared-reopen/compare.py and its instructions with these builds.
