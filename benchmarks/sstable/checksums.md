# Google CRC32C from Lean

Run the checksum-only benchmark from the repository root on Linux x86-64 with GCC, `taskset` and the pinned Lean toolchain.

```sh
BENCH_CPU=4 bash benchmarks/sstable/run-checksums.sh
```

Set `BENCH_CPU` to an allowed CPU. The default is the first CPU in the runner's affinity mask. The runner builds the shared Lake target for pinned Google CRC32C 1.1.2.

The benchmark makes direct calls to the native Lean binding over eight deterministically generated byte arrays per size. Each of seven trials hashes 64 MiB after 1,000 warmup calls. Every call starts from CRC zero, and the trial retains a checksum sum. Timing includes the Lean loop and FFI overhead.

Checks outside the timed loop cover the CRC32C test vector, incremental operation and empty input. The benchmark also compares the native and portable Lean implementations on all timed inputs with two initial CRC values.

| Bytes per call | Median ns/call |
| ---: | ---: |
| 32 | 3.18 |
| 256 | 9.48 |
| 1,024 | 32.97 |
| 4,096 | 128.08 |
| 16,384 | 492.11 |

Measured on CPU 4 of an AMD EPYC 9V45 with SSE4.2 exposed, Linux 6.18.57, Debian 13, GCC 14.2.0 with `-O3 -DNDEBUG` and Lean 4.36.0. These timings cover checksum computation on warm buffers. [Raw timings](checksum-trials.csv) · [Previous backend comparison](history/checksum-comparison.md)
