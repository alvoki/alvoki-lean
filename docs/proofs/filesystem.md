# Filesystem contract for the Linux adapter

The theorem is relative to the contract of the stock sequential Linux adapter, compiler, runtime, filesystem and device. The marked recovery slice starts with a durable directory and matching checkpoint. Fresh bootstrap must establish the corresponding initial state. The cooperating writer holds the physical lock in a stable canonical directory. Lock creation can precede acquisition. Managed names change only through the observed operations under the lock. Follow one root and its parent binding, and prove required private scratch and live-file non-aliasing at the reached operations. [Premise provenance](native-storage.md#premise-provenance)

| Boundary | Evidence needed for completion |
|---|---|
| Open, read and directory scan | Connect no-follow stat, open, stable binding, file description, cursor and exact bytes through each reached read and release. A clean EOF supplies a complete held enumeration. A read error after some entries must preserve the error. Derive the selected manifest, matching run bytes, marker and ordered WAL extents from the same physical view. Preserve the previously synced WAL prefix through partial append. |
| Writes and barriers | Buffered write success includes a successful explicit flush. Finalization can write more. An error reported only by fclose falls outside the successful explicit-flush observation. Keep the reported bytes and diagnostic at each boundary. A successful file fsync establishes durable bytes on its issued inode. A same-directory rename changes the visible binding atomically. Directory fsync settles visible child names, with a separate premise for the directory in its parent. Grouped sync attempts all members after an error. A failed barrier can have applied its effect. Preserve joint name and inode-byte choices through later effects and select one allowed image at reboot. |
| Lock and descriptor lifetime | Track the same open descriptions through allocation, duplication, fd-number reuse, private fork, close-on-exec, successful exec, explicit close, process exit and last drop. Carry those identities through every relevant native call, including delayed writes or syncs on the old keeper or retained directory after owner death. Account separately for machine restart and process exit with dirty data still visible. Derive lock vacancy and owner changes from the observed references. |
| Resources | In the pinned Lean 4.36 Linux runtime, raw open followed by failed `fdopen` can leave a live descriptor and newly created stage name. Repeated failures require an explicit resource condition or runtime fix. Treat truthful read, sync, lifetime and device reports as primitive assumptions. Derive internal WAL selection, phase, cache, cleanup and replay facts in Lean. |
