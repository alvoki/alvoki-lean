# Native L0 acceptance suspended: the phase heap has no inhabitant

**Decision requested:** review this diagnosis, the scope of the proposed replacement and the validation gates before migrating the native proofs. The pinned milestone 3 code is `335bbff0`. The integrated PR #5 baseline is `13a655ea`. The latter retains PR #33 and has the same segmented WAL phase contract. The public native safety, interruption and healthy theorems requiring `PhaseMemory` have an impossible premise. They supply no native correctness guarantee. The abstract client and component results whose assumptions do not include that heap can still be reviewed on their own terms. Native fixtures remain observations of those runs.

## Reproduce the contradiction

Run `ALVOKI_TOOLCHAINS=/path/to/alvoki-toolchains bash scripts/check-phase-memory-audit.sh` on this checkpoint, with the repository's Lean 4.36.0 toolchain. It builds the dependency from source, compiles the negative and positive proof modules into a temporary directory, replays them with leanchecker, and executes a small runtime probe. The counterexample was also replayed directly against each pinned baseline's build. It is a theorem about the old signature and belongs outside the production import graph. After migration keep that regression pointed at the historical declaration or an exact copy with its provenance. [Counterexample](../../tests/l0-audit/PhaseMemoryCounterexample.lean) · [Check script](../../scripts/check-phase-memory-audit.sh)

Let W be the type of worlds. Fix a reference r with payload W → Bool. For every f of that type, the unrestricted set law produces a world u in which r holds f. The read law then makes the function returned by get at u extensionally equal to f. Choose f(w) to negate the result of reading r at w and applying the returned function to w itself. Evaluating the equality at u gives b = !b. The proof needs one initial world and one reference. It needs no filesystem, mutation history, mutex law, assumed read success, cross-reference alias, or axiom about IO primitive semantics. Restricting only mutex frames, or adding an ownership precondition solely to consumers of the old heap, leaves the contradictory pair intact.

The historical choice is visible in `14fffca4`: the concrete WAL opener needed its active slot to survive allocation of its phase cell and mutex. The abstraction offered one heap for every reference payload. The usage motivating the abstraction was first order. The signature silently admitted higher-order payloads observing the entire semantic world. Later consumers diligently threaded the *same* heap through multiple operations, which improved resource identity while inheriting its impossibility. [Original change](https://github.com/alvoki/alvoki-lean/commit/14fffca4) · [Pinned declaration](https://github.com/alvoki/alvoki-lean/blob/13a655eadd4967b08da6acc54ae9bf8f2a393ce4/lean/Alvoki/Experiments/WAL/Segmented/Native.lean#L494)

A second checked theorem, `unrestrictedAllocationFalse`, uses only allocate and read. Diagonalize over an address/world pair. Allocate the predicate that negates its observation at that pair and apply the claimed exact read-back to the very address and world returned by allocation. This still contradicts itself when the set law is removed entirely. Restrict the allocation payload and its occurrence as well as subsequent updates.

## Replacement design

The independent review also checks `noUniversalReader` and `noLiveActionSlot`. Even granting one already-live IO.Ref (BaseIO Bool) at one reachable start does not suffice. For any Boolean predicate f on W the action w ↦ (f w, w) is a legal mathematical payload of that type. Unrestricted set and exact get would realize *every* f at that same reference. The diagonal then applies unchanged. This is why the choice of payload language matters as much as an ownership precondition. The review's two-slot model and clobber control are small tests of this principle. [Reviewer’s experiments](https://github.com/alvoki/alvoki-lean/blob/1f1a390ca814043b39c14c5648c360e8cfa563c2/docs/reviews/native-l0-335bbff0/PremiseExperiments.lean) · [Methodology](https://github.com/alvoki/alvoki-lean/blob/1f1a390ca814043b39c14c5648c360e8cfa563c2/docs/reviews/native-l0-335bbff0/methodology.md)

### Two feasible interfaces to investigate

| Criterion | A. Concrete native reference contracts | B. Explicit operational role model with a native boundary |
| --- | --- | --- |
| Shape of a primitive claim | For this allocation in the concrete opener and this designated first-order phase or slot, borrow under the owning scope. At the actual get/swap occurrence observe the previous payload and next ownership. A frame names the other live allocation. | Interpret the same instruction on a first-order heap with addresses and generations. Execution produces the new heap, result and authority. Prove the operations and disjoint frames once. |
| Realizability | Limited payloads exclude the particular higher-order embedding. A closed Lean witness over the *actual opaque primitives* remains unestablished. A local contract could still be jointly impossible or vacuous on a path. We tested real references, identity confusion and a retry on the shared installer. This tests a finite instance. | The pilot constructs one interpreter, all its laws and occupied states. A model witness can settle satisfiability for these laws. The native correspondence remains external unless derived for the actual primitive implementation. |
| Cost and reuse | Smaller initial diff for Registered, scan and cleanup because their postconditions already name IO worlds. Each new operation or protocol must transport matching identity and frame reports. Cost and trust grow if every caller supplies its own correspondence. | More work initially to index reached states and compose model/IO outcomes on the same issued calls. Subsequent rotation, flush and retry can reuse model transitions, registration and disjointness. Pure WAL/replay, builder induction and client traces need little change. Cut classifications still need an explicit correspondence for the in-flight leaf. |
| First falsification | Supply two actual slots with equal initial contents. Spend the supposed authority and observe the original allocation to distinguish them. An adapter assuming only value agreement will accept the wrong slot. | Change a model write to clobber an adjacent resource. Require the same model's next consumer and frame law to reject it. Then repeat the wrong-identity test at the IO boundary; a model-only control cannot catch a miswired adapter. |
| Consequence for the public theorem | Leave a narrowly named, reachable occurrence report external. Record its caller and evidence. Do not replace the old heap parameter by per-callback assumptions of equivalent breadth. | Require an admissible trace linked to the actual execution. Derive model facts from its issued actions. An independently chosen trace is insufficient even if its abstract return value agrees. |

**Recommendation for review.** Choose B for internal reasoning and use A only for the native leaf correspondence. The next vertical experiment should use one root, one store, one installed child, the actual produced authority, a subsequent consumer and a retry after fault. Decide on migration only after the adapter identifies the same allocations and reached states on that experiment. If A alone can provide an independently justified *joint* instance with a shorter proof, it remains a viable alternative. A per-role heap ranging over arbitrary Lean types is unnecessary in either design.

**Proposed semantic carrier.** Give the proof interpreter a first-order state and index its operations by issued occurrences. Start with a segmented WAL phase cell and active-child slot. An allocation returns a typed cell identity and ownership in the resulting state. Distinct allocations must be distinct *within* a role as well as across roles. A read consumes a live owned cell at an actual instruction and returns its recorded first-order value. A swap also returns the old value and establishes the new one. Set and release require the ownership of the named cell. A frame requires a different allocation and a transition whose write set excludes it. A stale generation or released capability cannot authorize a subsequent operation. The closed L0 phase, child cursor and row supplier should enter as separate roles only when a concrete consumer needs them. Payload descriptions can contain first-order IDs, bounded data and lists. They cannot contain arbitrary Lean values, semantic worlds, arbitrary functions, or closures carrying a handle implementation.

**Dataflow for a migrated consumer.** Start with the actual acquisition occurrence. Allocate the slot, publish the selected child into it, allocate the phase with that store ID and bind the new mutex to the phase. Return the phase/slot identities together with the reached state and registration. Scan consumes that registration. A rotating append takes the old child, installs its concrete successor and returns an updated registration on the same store. Keep initial acquisition as historical provenance and current child as replaceable ownership. The old definition of Original is unsuitable as a permanent requirement on the *current* child. Closure must be demonstrated by using the successor in flush and then in get on that handle.

**Runtime boundary.** Move frame and ownership proofs onto the shared executable recipes with a model interpreter and an IO interpreter. At an IO leaf, relate the observed result, operand and successor event to the model step for that invocation. Physical observations such as fd identity, file contents and lock ownership require separate local evidence. Do not postulate that every mathematical input to opaque `IO.Ref.set` or `get` over every world realizes a model transition. In particular, do not simply replace polymorphic PhaseMemory with four globally quantified tables of equally opaque IO calls. Even a fixed payload would still require a justification tying a reachable allocation to observations. `ST.Ref` in Lean 4.36 has an opaque address carrier and a proof of payload nonemptiness. Two different Lean type annotations alone are insufficient allocation evidence. `lean_io_mk_world()` returns `lean_box(0)` in the runtime header. A runtime token is not an observation of the heap at two different moments. This fact about compilation is not a Lean proof that the opaque type W is a subsingleton. [Pinned Lean ST definitions](https://github.com/leanprover/lean4/blob/v4.36.0/src/Init/System/ST.lean) · [Runtime header](https://github.com/leanprover/lean4/blob/v4.36.0/src/include/lean/lean.h)

**A decision that remains open.** If a source-level relational interpretation can account for every issued native step, the top theorem should take admissible executions of that semantics and refine their traces. If the only available link to stock Lean/Linux is externally supplied per-primitive correspondence, name it at the public theorem and demonstrate its joint plausibility on actual traces. Neither approach justifies equating an arbitrary model run to a native execution or assuming the whole operation's trace as a primitive law. Re-establishing which form of native acceptance can honestly be offered is part of the first migration review.

## Three kinds of evidence

| Question | Evidence required at this checkpoint or migration gate |
| --- | --- |
| Are the role laws jointly satisfiable? | Construct the operations and all laws in Lean from one model with named cells and at least two distinguishable reached states. Also construct an occupied precondition and run a mutating consumer. A theorem starting with a heap parameter or an instance with every ownership predicate False fails this test. The included [role model](../../tests/l0-audit/OwnedRoleModel.lean) is a pilot, not an inhabitant of the old contract. |
| Do programs compose in that interpretation? | Instantiate a shared recipe, thread the actual returned cell into a following operation and frame the other cell. Before migration acceptance, extend the witness to the *joined* phase, child, disk and descriptor contracts, including an error continuation and a rotated registration. Independent inhabitants with incompatible resource projections do not suffice. |
| What does the runtime actually do? | The [IO probe](../../tests/l0-audit/PhaseInstallProbe.lean) exercises both production install recipes with real references, a mutex and first-order child IDs. Failure of mutex acquisition triggers cleanup. Retry uses the same slot, then a consumer swaps the returned phase and writes through the child slot it contains. Passing a different allocated slot with equal initial contents makes the consumer check fail. This is a real run of the recipes, not a complete WAL open or a universal semantics. The next probe should record allocation and occurrence IDs and compare the same operation trace against the model, including faults. Keep the local Linux assumptions explicit. |

The leanchecker result says that each proof term typechecks. The axiom policy checks the constants on which that proof depends. A parameter H is neither a new axiom nor evidence that H has an inhabitant. Deriving success from H plus healthy reports also cannot witness H. This is why adding a positive return case, auditing axioms, running Linux fixtures and obtaining a green cold build all missed P0. Put a *closed constructor plus reached execution* beside each future external-contract family. Review the witnesses again whenever a new consumer combines two families. Try the diagonal payload, a forged reference, a stale capability and an aliased inode as boundary tests. Use a deliberately broken set or frame operation to check that the witness actually observes the affected resource. Keep the failed-fdopen exclusion explicit when testing descriptor lifetimes.

The positive pilot actually runs both `installReopenedWith` and `installPhaseWith` over EStateM. The recovered child is input. `realized` constructs the full model record; `reached` consumes it across two writes on separate cells. `mutexFailure` returns failure from the shared install and runs cleanup; `reuse` rejects a stale key after reallocation at the same address and role. In `retryHandoff` the first install fails at the occupied mutex address. The other owner releases its key on that very failure heap; retry allocates a fresh phase and the new generation of the mutex. The next consumer runs the production updateWith, appendOwnedWith and checkAppend recipes with the selected live child. A different live child with identical contents is refused on the same ready heap. This example models an in-place write to a child log, not rotation or durable bytes. The failed phase cell remains allocated. The clobbering interpreter preserves its own target fact (`clobberKeepsTarget`) but provably violates the joint contract (`clobberRejected`). These finite slots model ownership tests and disjoint frames, not exclusive possession of an unforgeable capability, mutex scheduling, swap atomicity or reference counting. Those four properties remain to be specified where the first migration consumer needs them.

## Adjacent contracts and next correctness checkpoints

A targeted signature survey on `13a655ea` found the unrestricted payload/read-back pair in PhaseMemory. The single-file ChildMemory uses a fixed child phase and a cursor rule guarded by binding and ownership. L0 PhasePrimitives reads the named L0 phase under Owned. The table writer's row cursor is fixed to Rows. None supplies the diagonal storage law above by itself. Polymorphic bind and cut induction over propositions also does not store arbitrary functions for later read-back. This inspection is not a joint model of those contracts. In particular, RootLifetime can interpret privateBorrow as True and liveAtReturn as False regardless of descriptor observations. That is a *too-weak interpretation*, different from an uninhabited premise. | Manifest writer lifetime and inode provenance, physical defect | Pin one inode at staging open. Keep descriptor-to-inode binding through write and sync. The correctness gates above are separate reviews. This design checkpoint preserves the integrated code for comparison and records the audit correction in the retrospective. It does not reinstate native acceptance.
