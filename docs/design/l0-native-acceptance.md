# Acceptance boundary for native L0

**Independent audit correction.** The required PhaseMemory has no inhabitant. The native theorems that assume it are vacuous, including the healthy examples described below. The [counterexample, design and validation gates](l0-phase-memory-audit.md) supersede the earlier native acceptance assessment.

An audit can begin with the theorem in the second column and trace its data back to a primitive report or a producer in the same run. The [review inventory](l0-native-review.md) maps those producers to their files.

## From execution to a cut

There are three separate checks. First, the ordinary projection of the observer equals the executable result **and final world** for the identified invocation. Second, the observer is built from the actual reserve, scan, append or table/publish and finalization recipes. Bind continues at the returned operand and world. Result handlers also run on errors, and only on returned actions. Structural proofs follow the real branches, including repeated WAL reads to EOF and close on an already-closed child. Reverse classification takes a single raw cut and locates it without a phase hint from the caller. Third, each leaf has an admitted in-flight effect relation and physical frame. Erasure alone imposes no condition on an observer's cut field. Classification alone cannot validate the leaf contract against Linux. A reviewer should check all three, especially when a call is moved inside a helper or across an FFI boundary. [ObservedIO](../../lean/Alvoki/Experiments/L0/ObservedIO.lean) · [WAL public cut interpretation](../../lean/Alvoki/Experiments/WAL/Segmented/Proofs/PublicAppendCut.lean)

Checked directory enumeration, for example, is an issued native primitive. Its interruption contract bounds the protected physical effects over the call. The model does not enumerate C instructions, machine scheduling points or all possible device failures. By contrast, separate Lean-level iterations which issue fresh reads have separate operands and cuts. A temporary extra rename in the real publisher broke the correspondence proof. That negative control probes one path and complements structural review of the other paths.

## What the environment supplies

* A stable owned namespace, initialized image and durably named parent. Frames and separation tie descriptors and directory names to particular inodes. Staging cannot alias a protected file through an unaccounted hard link. Phase and child facts are about the owned reference and selected registration on the same heap.
* The specified local read, write, buffering, lock, file-sync and directory-sync effects, including possible effects before an error report. Recovery assumes the chosen bytes are available for persistence. Misleading clean cache bytes after lost writeback are excluded. A later successful sync alone cannot certify repair.
* The Linux/Lean runtime's scoped handle, non-escape and last-reference disposal assumptions. An unlock attempt has its own reported outcome. A last-reference drop is a separate event. Under Lean 4.36 a raw descriptor acquired before a failing fdopen can leak before there is a Lean handle. An exclusive create can also leave a name. The public scope theorem does not repair either runtime behavior.
* The physical interpretation of process exit and of allowed power-loss survivors. The native tests inject failures at the file and directory barriers, lose delivery, kill processes and reopen. They leave the kernel running. Kernel replay checks the Lean derivations under the stated premises. Neither test is an empirical demonstration of a particular device losing power.
