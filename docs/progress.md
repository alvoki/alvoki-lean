# Current handoff

The Linux adapter uses one WAL, a durable commit marker and strict v2 checkpoint manifests over immutable v3 runs. It supports sequential writes, snapshots, compaction, checkpoints, recovery and opt-in collection of obsolete run generations. [Active storage protocol](architecture.md#sequential-storage)

Under the documented I/O contracts, the strict v2 proof follows exact locked reads after repeated failures and returns the table and generation selected by the recovered checkpoint and marker. An interrupted checkpoint preserves the acknowledged WAL. An uncertain write may add its one submitted frame. The checkpoint proofs share typed contracts for durable ordered run files and the exact restored table. The v2 proof no longer creates a synthetic v1 manifest to reuse the loader and run-set guarantees. Live lock and descriptor lifetimes and primitive effect reports still need to be connected to the complete native trace. [Verification status](verification-status.md) · [Disk proof obligations](proof-roadmap.md#disk-guarantees-to-prove)

The separate segmented WAL worker validates the strict checkpoint, selects marker-covered bytes and repairs the last required segment. From a complete lock-held inventory, exact read reports and healthy repair effects, Lean derives that the final retry returns the same table, generation, byte count and segment and leaves them durable.
