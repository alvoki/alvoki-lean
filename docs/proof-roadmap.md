# Proof roadmap

The stock Lean v1 API and the v3 compaction prototype now have executable codec, merge, and read refinements. The sequential table model lifts v3 retention to older and newer runs and active snapshots. Persistent storage and concurrent publication still need engine contracts and implementations. [Current proof inventory](verification-status.md) · [Engine roadmap](roadmap.md)

## Codec guarantees we already have

| Code | Kernel-checked guarantee |
|---|---|
| `splitByte`, `joinBytes`, `pushWordFast`, and `word` | Joining the eight little-endian lanes of a word recovers the word. Extracting a lane after joining recovers that byte for lanes 0 through 7. Reading at the old length after appending a word returns that word, for any prefix. |
| `wordFast`, `wordMachine`, and checked packed access | `wordFast` agrees with `word`. The machine-offset reader agrees with the byte reader when the word extent is in bounds and the array size fits. Checked record access agrees with the logical record at its index and returns `none` outside the run. |
| `encodeV1` → `parseRun` → `Run.decodeV1` | For a strictly ordered record array whose count fits a 64-bit word and whose full byte length fits the parser's machine bound, parsing succeeds and decoding returns the exact input array. |
| `parseRun` → `Run.decodeV1` → `encodeV1` | Every accepted v1 block re-encodes to its exact original bytes, including header and payload. |
| `parseView` and `View.logicalRecord` | Acceptance preserves the input bytes, count, version, and layout. Logical keys are strictly ordered. The record-offset theorems cover interleaved v1 and columnar v2 layouts. |
| `ScopedBytes.Builder` | Appending a valid slice preserves the prefix and adds its exact bytes. Appending a list of slices agrees with their ordered concatenation, and combining adjacent slices preserves the bytes. |

The full-block round trips name the executable codec in `BlockCodec`. The baseline, scalar, and indexed codec results below extend the same canonical bytes or decoded records to those entry points. Independent fixtures also check both stock v3 writers and scans. ## Versioned compaction and its codec

### Logical histories and retention

- [x] `winner_latest` proves that a snapshot selects the largest eligible sequence. `winner_union` resolves equal key-and-sequence ties in favor of the right input. `read` projects the winning value only after resolving precedence, so a winning tombstone yields absence.
- [x] `retain_key` characterizes the retained rows for each key as every row above the floor followed by the first eligible row at the floor. `winner_retain` preserves every key at every snapshot at or above the floor. The proof ranges over all `UInt64` keys and sequences, including both endpoints. `retain_ordered` and `versions_unique` preserve ordering and uniqueness.
- [x] `winner_retain_in_context` preserves the winning entry with older runs in the read context, including boundary tombstones. `winner_advanceFloor` preserves reads still supported by the higher floor. [Logical compaction theorems](../lean/CompactionModel.lean)

### Executable v3 format and kernels

- [x] `parse_iff` characterizes acceptance by exact header, count, length, machine-size bound, key and sequence ordering, and canonical tags and tombstone payloads. Named rejection theorems cover short blocks, versions, lengths, order, duplicates, tags, and nonzero tombstone payloads. [Byte validity](../lean/Compaction.lean) · [Rejection corollaries](../lean/CompactionCodec.lean)
- [x] `encodeV3_roundtrip` and `decodeV3_reencode` recover the original canonical rows and original accepted bytes respectively. The packed field refinements connect the selected positions to natural byte offsets, and `encodeV3Row_extract` proves the exact bytes of each in-bounds source slice. [Codec proofs](../lean/CompactionCodec.lean)
- [x] `compact_eq_encode` and `compactSpans_eq_encode` prove both writers emit the exact reference encoding of the retained history. `compact_roundtrip` gives parser acceptance for parsed inputs when output length fits a machine word. `compact_history` links a reparsed output to the sequential model's run replacement. [Compaction refinements](../lean/CompactionProofs.lean)
- [x] Both executable scans refine a fold over the exact visible rows in increasing key order. `compact_visibleRows_eq` proves row equality before checksumming and `compact_scan_eq` gives checksum equality at supported snapshots. [Scan refinements](../lean/CompactionProofs.lean)

## V1 API and codec contracts

- [x] **Parser and canonicality.** `parseRun_iff` characterizes v1 acceptance by the version, exact count and length, machine bound, and strict natural-offset key order. The rejection corollaries cover short headers, mismatched versions or lengths including truncation and trailing bytes, and non-increasing keys. `decodeV1_reencode` gives canonical bytes and `encodeV1_injective` makes that encoding unique on valid record arrays. [Parser and API proofs](../lean/RunProofs.lean) · [Canonical codec](../lean/BlockCodec.lean)
- [x] **Lookup and range.** `Run.lookup_some_iff` and `Run.lookup_none_iff` characterize the executable result against decoded records. `Run.rangeRows_eq` identifies the exact decoded interval in key order. `Run.rangeChecksum_eq` and `Run.rangeChecksum_empty` connect the packed loop to that list, including empty and reversed ranges. [Parser and API proofs](../lean/RunProofs.lean)
- [x] **Merge.** `mergedRecords_ordered`, `mergedKeys_unique`, and `merge_eq_encode` establish the format and ordering. `merge_roundtrip` gives acceptance when output length fits. `merge_lookup` gives right-preferred map union and `merge_lookup_absent` identifies exactly the union of input keys. The existing adaptive, bounded-window and checked streaming replay equality theorems transfer these guarantees to those paths. [Merge API proofs](../lean/RunMergeProofs.lean) · [Writer equalities](../lean/MergeProofs.lean)
- [x] **Codec variants.** The baseline, scalar and indexed encoders emit the canonical v1 bytes. The decoder theorems connect baseline, scalar and packed materialization and the streaming checksum to the decoded records. `storeWord_byte` gives exact little-endian bytes in the written interval and preserves all other positions. The indexed loop proves the full byte output, machine offset bounds and scalar fallback. [Codec equivalences](../lean/CodecVariants.lean) · [Store contracts](../lean/Optimizations.lean)
- [ ] **V2 if adopted.** The columnar layout is experimental. A supported v2 encoder would need full round trips and complete acceptance and rejection coverage. Prove interleaved and columnar encodings for the same records have identical observable lookup and scan results. [V1 and v2 formats](specifications.md)

A bit change can produce another valid v1 block. If a format gains a checksum, prove the covered bytes, placement, and reader/writer contract with explicit assumptions about detectable corruption. If a codec gains streaming framing, prove exact byte consumption and that truncated frames cannot yield complete records. [Current file formats](specifications.md)

## Refine alternative paths when they become supported

| Candidate | Proof to add before depending on it |
|---|---|
| Prepared replay and online replay coalescing | Plan construction preserves each validated move's source bytes and order. Grouping adjacent slices preserves the full stream, and each executable writer equals checked streaming replay. |
| Disjoint merge, eager spans, and comparison-selected scan | Each enabled shortcut agrees with the proved merge or direct fold, including empty inputs and boundaries where adjacent ranges touch. |
| Packed value transforms | Output parses with the same key order. Unchanged bytes are preserved and each target value satisfies the specified transform. |
| Native fixed-width copy or scoped builder | Every fast-path guard justifies the bounds, overlap and exclusivity conditions. The native implementation returns the exact bytes and length specified by the Lean contract, preserves aliases, exposes only initialized bytes, and agrees with stock behavior on fallback. Record compiler, runtime, and ABI assumptions. |
| Packed Rust as a supported engine path | Apply the shared byte-format and snapshot specifications to the Rust code actually shipped. Link its packed operations to the verified search behavior and prove the safety and semantics of any enabled unsafe kernels. |

Benchmark-only variants can retain exact-output differential tests and code-generation checks. Each promoted implementation should refine an existing contract, so higher-level proofs apply across choices. ## Carry the proofs into storage-engine features

- [x] **Sequential multi-run model.** The snapshot table gives each acquisition a table-local handle and assigns write sequences above the committed watermark. Floor advancement checks at most one comparison per active pin, plus the current floor bound. The trace theorem proves point and range reads stay stable for a handle through writes, flush, adjacent compaction, and checked reclamation. The reclamation check compares actual before and after run lists at the floor and the affected key’s version boundaries, then lifts equality to all supported snapshots. [Snapshot table](../lean/Alvoki/Storage/Table/SnapshotTable.lean) · [Run-level reclamation](../lean/Alvoki/Storage/Table/SequentialPurge.lean)
- [x] **Executable sequential table.** The packed v3 point and range readers agree with decoded history. The packed table refines the snapshot model for write, pin lifecycle, lookup, range, successful flush and successful adjacent compaction. Fixed and generated traces compare the actual API with the model. [Packed table](../lean/Alvoki/Storage/Table/PackedTable.lean) · [Packed read proofs](../lean/Alvoki/Storage/Table/CompactionRead.lean)
- [x] **WAL, manifest, and replay.** The codecs round-trip byte-exactly. The replay theorem covers the committed prefix, a contiguous surviving suffix and a final incomplete frame. The Linux adapter installs immutable run generations and reopens from the installed manifest. Interrupted publication and torn-tail repair have local I/O fixtures. [Replay theorems](../lean/Alvoki/Storage/Disk/Recovery.lean) · [Durability protocol](architecture.md#sequential-storage)
- [x] **Working-directory independence.** `DiskTable.open` resolves one absolute directory before opening its lock. `DiskDirectory.paths_independent_of_cwd` covers the root and every file role used by the adapter. The native fixture changes the working directory with two databases open and verifies lock aliasing, file writes, checkpoint publication, and reopen. The adapter relies on the canonical directory and its entries remaining under engine control while open. [Disk adapter](../lean/Alvoki/Storage/Disk/DiskTable.lean) · [Native fixture](../lean/Alvoki/Checks/DiskTableChecks.lean)
- [x] **Durable WAL boundary.** Write acknowledgment follows sync of the WAL and staged marker, marker rename, and directory sync. `write_cut_replays_old_or_new` and `acknowledged_write_replays_new` cover modeled append and marker publication cuts given an already durable prefix. Native tests cover full-size and valid uncommitted frames, both sides of marker rename, and corruption in the committed prefix. [WAL boundary model](../lean/Alvoki/Storage/Disk/WalBoundaryModel.lean)
- [x] **Selected WAL sequence integrity.** Disk recovery checks every frame's checksum and expected ordinal in the prefix selected by `WAL.commit`, including frames covered by the checkpoint. The audit checks that ordinal-aware decoding accepts correctly numbered histories and that a successful decode has contiguous ordinals starting at one. The native duplicate-frame fixture rejects corruption below the checkpoint watermark. [WAL decoder](../lean/Alvoki/Storage/Disk/WriteAheadLog.lean) · [Native fixture](../lean/Alvoki/Checks/DiskTableChecks.lean)
- [x] **Checkpoint publication for a fixed synced WAL.** The adapter and model share the run writes, file syncs, directory barrier, and manifest replacement schedule. `checkpoint_retry_valid` preserves exact durable run bytes for each recoverable manifest during interrupted publication, crash, and reopen. `recoverRunSet_committedBoundary` shows that those checkpoint and selected WAL bytes pass the actual loader and frame-count guard under a valid replay history. [Checkpoint model](../lean/Alvoki/Storage/Publication/CheckpointPublicationModel.lean) · [Disk adapter](../lean/Alvoki/Storage/Disk/DiskTable.lean)
- [ ] **Filesystem crash refinement and reclamation.** Prove the disk guarantees below, then implement and verify collection of obsolete generations, covered WAL segments, and old versions. [Reclamation contract](#garbage-collection-contract)
- [ ] **Indexes and filtering if adopted.** Prove that indexes identify all eligible records, that a negative filter result cannot hide a present key under the declared construction assumptions, and that indexed reads agree with reference scans.
- [ ] **Concurrency and transactions.** Specify the isolation level before proving it. Show that concurrent reads, writes, snapshot lifecycle, and background compaction refine that contract. For transactions, prove atomic effects and the chosen visibility and conflict rules.
- [ ] **Remote storage and reactive views if adopted.** Specify the object-store consistency and publication assumptions. Connect version selection and recovery to that model. Prove that incremental materialization agrees with recomputing the query at the same snapshot under the declared event-order and replay rules. [Engine roadmap](roadmap.md)

## Disk guarantees to prove

`recoverRunSet_written` starts from the correct run files and a WAL consisting of complete valid records followed by fewer than 48 bytes. The missing refinement connects these hypotheses to every state that the adapter can reach, including retries and crashes during recovery. Express the executable protocol against file operations shared by the Linux adapter and a fault-injectable model. Model visible and durable directory entries separately from file contents, with explicit rules for file sync, directory sync, rename, failed operations, and interrupted appends. Inject a crash or failure at each operation boundary, including during reopen. [Current recovery theorem](../lean/Alvoki/Storage/Disk/DiskTable.lean) · [Publication sequence](architecture.md#sequential-storage)

The single-file replacement model now executes the same sequence as the Linux adapter uses for WAL repair and manifest replacement. File sync establishes the staged contents. Rename exposes the replacement and permits either name binding after a crash. Directory sync settles the replacement. `repair_retry_preserves_replay` covers any number of interruptions and retries when the starting WAL images agree on replay and each attempt uses the actual tail-trimming function. The model assumes the containing directory already exists durably and that recovery owns the staging name. It takes the initial active file images as inputs. Modeling in-place appends, initial WAL creation, checkpoint run-set durability, and lookup outcomes remains necessary for the full recovery theorem. [Shared sequence](../lean/Alvoki/Storage/Publication/DiskPublication.lean) · [Publication model](../lean/Alvoki/Storage/Publication/DiskPublicationModel.lean)

## End-to-end storage guarantees

The top-level target is **refinement of the executable storage engine to the abstract database across crashes**. For every execution admitted by the filesystem model, there is a legal abstract history that explains its successful reads, acknowledgements, and reopened states. The history includes every acknowledged write in order and may include an unacknowledged write that became durable. Every applied write originates in a submitted operation. Writes that did not survive a crash are dropped from that session's history before considering submissions in the next session.

The refinement must apply to the protocol used by the Linux adapter, under explicit filesystem and resource assumptions. Keep the working-directory change and failed directory sync followed by retry as fault fixtures. Include crashes during recovery itself. The theorem and fixtures should account for these traces through the same file operation contract. [Disk guarantees](#disk-guarantees-to-prove)

The first marked-state slice assumes an owned, already durable directory with stable names, non-aliasing staging and live files, one sequential writer and a durable matching checkpoint. In-place append must preserve the previously synced WAL prefix even on interruption. File sync establishes durable file contents. Same-directory rename changes the visible binding atomically, and directory sync settles the visible names. A crash before that barrier may retain the old binding or the new one. Process death can leave unsynced effects visible. Failed syncs may have applied some or all of their effects. With the host's GNU Coreutils 9.7, tracing `sync -- missing DIR` confirmed that it still calls `fsync` on `DIR` after the first open fails and then exits with an error. The native partial-effect fixtures use the real sync for just the second target. The kernel, filesystem and storage-device behavior during power loss remains part of the contract. [Native fixture](../lean/Alvoki/Checks/DiskTableChecks.lean)

| Proof target | Property |
|---|---|
| Recovery progress | Once crashes stop and required file operations succeed, reopening a reachable state with healthy storage and sufficient resources terminates successfully. The recovered state survives further crashes with no intervening writes. State separately which integrity failures require recovery to report corruption. |
| Maintenance preserves reads | Arbitrary scheduling of flush, compaction, and restart preserves point and range results for snapshots the API promises to serve. Include tombstones that mask older values. Pins constrain the retention floor while active, and a new session can acquire a fresh handle to a retained sequence. |
| Crash-safe reclamation | Prove both preservation of recovery and supported reads and eventual collection of eligible data. Cover every deletion step and repeated crashes during collection. [Reclamation contract](#garbage-collection-contract) |
| Atomic batches and retry identity | A crash exposes all effects of a batch or none. A durable request ID allows a client to retry an ambiguous submission and get the original result without applying the batch twice. Specify how long IDs are retained and what happens when an ID is reused with a different request. If concurrent transactions are added, specify the isolation level and consider strict serializability as a separate target. |
| Recovery work and retained space | Bound replay work in terms of WAL length and memtable size. Bound retained bytes in terms of live data, retained versions, pinned snapshots, and the checkpoint and compaction policies. Use operation counts for the proofs and the native replay benchmark for wall-clock regression checks. [Replay benchmark](benchmarks.md#disk-replay) |
| Backup and format migration | An online backup restores to a single consistent snapshot. A format migration preserves reads at every supported snapshot. After interruption, the durable metadata selects a complete database in a format its reader can open. |

Prove recovery safety and progress across repeated crashes first. Lift the existing snapshot and compaction laws to disk traces before enabling reclamation. Establish the replay work bound alongside the memtable redesign. Use the same durable publication guarantees when adding batches, backups, or migrations.

### Garbage collection contract

The engine must eventually reclaim obsolete run generations, covered WAL data, and versions that no supported snapshot can observe. The proof covers the executable collector, including interruption and retry.

1. **Publish before deleting.** Make the replacement run set, its directory entries, and the manifest selection durable. Prove that every manifest recovery can still select has intact runs and a complete WAL suffix. Keep runs held by current readers or by a backup once those operations can hold files independently of the manifest.
2. **Collect WAL by durable coverage.** Use sequence ranges recorded for WAL segments so the collector can delete whole covered segments. A segment is eligible when every recoverable checkpoint covers its last sequence and the segment is no longer active. Preserve every segment needed for replay. Prove that crashes during checkpoint publication, segment rotation, deletion, and directory sync leave a recoverable state.
3. **Preserve supported snapshots.** The packed collector must agree with point and range reads at every sequence the API can still serve. Advance the retention floor only as permitted by active pins. Verify tombstone removal in the context of all remaining runs and the memtable so an older value cannot reappear.
4. **Prove progress and bound space.** Once the files or versions stay eligible, I/O succeeds, and maintenance keeps running, they are eventually reclaimed. Repeating collection after a crash preserves the same logical state. Bound retained space by live data, required snapshot history, the uncheckpointed WAL, and the temporary space and backlog permitted by the checkpoint and compaction policies.

### Performance requirements for verified paths

Keep verification-only histories, invariants, and witnesses in the proof layer. Lean erases proof terms in `Prop` from native execution. Executable checks, stored metadata, and computations that feed runtime values still cost time or space. Prove the existing packed and machine-indexed kernels against the logical model, and validate filesystem and format invariants at the boundaries where the engine needs them.

Reuse the packed compaction traversal for version collection and file metadata for run and WAL eligibility. Use the exhaustive logical purge checker as a test oracle once a cheaper executable drop rule has a proof.

For any verification change that alters runtime code, compare the native release path with the same-machine baseline. Measure the affected reads, writes, compaction, checkpoint, or replay workloads. For reclamation specifically, track retained bytes and replay work during a sustained write and checkpoint workload, and measure foreground latency both during collection and while snapshots hold old versions. Inspect generated code where a proof-oriented refactor touches a hot loop. A regression requires an explicit, measured tradeoff before the changed path becomes the default.
